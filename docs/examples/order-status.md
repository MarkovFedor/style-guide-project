# Обновление статуса заказа

Справочный фрагмент для интегратора основного API. Операция изменяет статус существующего тестового заказа и добавляет запись в историю.

## Метод и путь

`PATCH /api/v1/restaurants/{restaurant_id}/orders/{order_id}/status`

Исходники: `app/api/v1/router.py`, `app/api/v1/endpoints/restaurant_orders.py`, `app/schemas/order.py`, `app/services/order_service.py` в коммите `89a3abe1c0ff8a86bf2aad9f09bc91669c58941f`.

## Параметры

| Поле | Расположение | Тип | Обязательность | Значение |
| --- | --- | --- | --- | --- |
| `restaurant_id` | Путь | Параметр пути; обработчиком не используется | Обязательно в URL | В примере `1`; фактически сервис получает константу `1` |
| `order_id` | Путь | Целое число | Обязательно | Идентификатор существующего заказа ресторана `1` |
| `status` | JSON | Строка | Обязательно | Одно из значений в словаре статусов |
| `comment` | JSON | Строка или `null` | Необязательно | По умолчанию `null` |

Допустимые значения: `pending`, `accepted`, `cooking`, `ready`, `delivering`, `delivered`, `cancelled`.

## Пример запроса

Требования: основной API запущен на `localhost:8000`, тестовый заказ `1` принадлежит ресторану `1`. Замените идентификатор, если такого заказа нет. Пример запроса не выполнялся в рамках лабораторной.

```bash
curl --request PATCH   'http://localhost:8000/api/v1/restaurants/1/orders/1/status'   --header 'Content-Type: application/json'   --data '{"status":"accepted","comment":"Заказ принят кухней"}'
```

## Ожидаемый ответ

Для существующего заказа — HTTP `200` с телом, формируемым обработчиком:

```json
{"detail":"Статус заказа #1 обновлён на accepted"}
```

| Код | Условие | Содержание |
| --- | --- | --- |
| `400` | Недопустимая строка статуса для найденного заказа | `detail`: `Недопустимый статус: unknown` при значении `unknown` |
| `404` | Заказ не найден среди заказов ресторана `1` | `detail`: `Заказ не найден` |
| `422` | Тело не содержит обязательного `status` или не соответствует схеме | Ошибка валидации FastAPI |

## Ограничения реализации

Параметр `restaurant_id` из URL не передаётся в сервис: используется константа `1`. Список статусов проверяется, но последовательность переходов не ограничена. Поэтому нельзя обещать переход только из «Принят» в «Готовится» или изоляцию произвольного ресторана по этому URL. Не используйте этот пример как доказательство готовности API к промышленной эксплуатации.
