# Структура документов

## Выбор типа

**S-01. Обязательно:** выбирайте структуру по задаче читателя. Подход Diátaxis помогает разделять обучение, практические инструкции, справочник и объяснение. Он не требует создавать четыре пустых документа для каждой функции.

| Тип | Задача | Минимальная структура |
| --- | --- | --- |
| Учебный материал | Освоить первый сценарий | Цель → подготовка → шаги → проверка → дальнейшие действия |
| Практическая инструкция | Решить конкретную задачу | Результат → требования → шаги → ожидаемый результат → ошибки |
| Справочник API | Найти точный контракт | Метод и путь → параметры → тело → ответы → ограничения |
| Объяснение архитектуры | Понять причины устройства | Контекст → компоненты → связи → решения → ограничения |

## Шаблон инструкции

**S-02. Обязательно:** используйте следующие разделы, если они применимы.

```text
# Название задачи
Кому адресован документ и какой результат он даёт.
## Требования
Инструменты, исходная версия, данные и рабочая папка.
## Шаги
Нумерованные действия и команды.
## Проверка результата
Наблюдаемый признак успеха.
## Возможные ошибки
Симптом, причина и следующее действие.
## Ограничения
Упрощения MVP и непроверенные условия.
```

Проверка: читатель может выполнить задачу без неявного знания локальных настроек автора.

## Шаблон правила

**S-03. Обязательно:** правило содержит уникальный идентификатор, обязательность, действие автора, положительный пример и способ проверки. Если полезно, добавьте отрицательный пример.

Пример: «C-01. Обязательно: указывайте язык блока кода. Пример: `bash` для команд. Проверка: Markdown-линтер и просмотр страницы».

Проверка: по правилу можно вынести обоснованное решение в PR.
