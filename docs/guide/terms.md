# Терминология

**T-01. Обязательно:** используйте предпочтительные термины из таблицы. Новые термины добавляйте через PR до массового использования.

| Термин | Значение и форма в коде | Не использовать как синоним |
| --- | --- | --- |
| Ресторан | Заведение, представленное `Restaurant` | Сервис-заведение |
| Клиент ресторана | Отдельный сервис `restaurant_client`, порт 8001 | Основной backend |
| Основной API | FastAPI-приложение `app`, порт 8000 | Клиент ресторана |
| Блюдо | Шаблон `Dish` | Позиция корзины |
| Блюдо ресторана | `RestaurantDish`, доступность и цена у ресторана | Любое блюдо без уточнения |
| Корзина | `Cart`, связанная с `session_id` | Заказ |
| Позиция корзины | `CartItem` | Заказ |
| Заказ | `Order`; при оформлении создаётся по ресторану | Корзина |
| Идентификатор сессии | `session_id`; не является доказательством авторизации | Токен доступа |
| Статус заказа | Поле `status` заказа | Статус оплаты `payment_status` |

## Статусы заказа

**T-02. Обязательно:** машинные значения записывайте точно, в кодовом оформлении. Русская подпись поясняет значение и не меняет JSON-контракт.

| Значение | Русская подпись |
| --- | --- |
| `pending` | Создан |
| `accepted` | Принят |
| `cooking` | Готовится |
| `ready` | Готов к выдаче |
| `delivering` | Передан курьеру |
| `delivered` | Доставлен |
| `cancelled` | Отменён |

Проверка: сравните таблицу с `valid_statuses` в `app/services/order_service.py` закреплённой версии. Не изображайте список допустимых значений как проверяемую сервером последовательность переходов.
